# Casos de uso

O [OpenTofu](index.mdx) é uma ferramenta de infraestrutura como código que
permite definir recursos de infraestrutura em arquivos de configuração legíveis
por pessoas, que podem ser versionados, reutilizados e compartilhados.
Você pode então usar um fluxo de trabalho consistente para provisionar e
gerenciar sua infraestrutura com segurança e eficiência ao longo de todo o seu
ciclo de vida.

Esta página descreve casos de uso populares do OpenTofu e fornece recursos
relacionados que você pode usar para criar configurações e fluxos de trabalho do
OpenTofu.

## Implantação multinuvem

O provisionamento de infraestrutura multinuvem aumenta a tolerância a falhas,
permitindo uma recuperação mais eficiente em caso de interrupções do provedor de
nuvem.
No entanto, as implantações multinuvem adicionam complexidade, pois cada
provedor possui suas próprias interfaces, ferramentas e fluxos de trabalho.
O OpenTofu permite que você use o mesmo fluxo de trabalho para gerenciar
múltiplos provedores e lidar com dependências entre nuvens.
Isso simplifica o gerenciamento e a orquestração de infraestruturas multinuvem
de grande escala.

## Ferramentas para implantação, escalabilidade e monitoramento de infraestrutura de aplicações

Você pode usar o OpenTofu para implantar, lançar, escalar e monitorar com
eficiência a infraestrutura de aplicações multicamadas.
A arquitetura de aplicações em N camadas permite escalar os componentes da
aplicação de forma independente e proporciona uma separação de
responsabilidades.
Uma aplicação pode consistir em um conjunto de servidores web que utilizam uma
camada de banco de dados, com camadas adicionais para servidores de API,
servidores de cache e redes de roteamento.
O OpenTofu permite gerenciar os recursos em cada camada em conjunto e lida
automaticamente com as dependências entre as camadas.
Por exemplo, o OpenTofu implantará uma camada de banco de dados antes de
provisionar os servidores web que dependem dela.

## Clusters self-service

Em grandes organizações, seu time centralizado de operações pode receber muitas
solicitações de infraestrutura repetitivas.
Você pode usar o OpenTofu para criar um modelo de infraestrutura "self-service"
que permite que as equipes de produto gerenciem sua própria infraestrutura de
forma independente.
Você pode criar e usar módulos do OpenTofu que codificam os padrões para
implantação e gerenciamento de serviços em sua organização, permitindo que os
times implantem serviços de forma eficiente, em conformidade com as práticas da
sua organização.
Um backend na nuvem também pode ser integrado a sistemas de tickets como o
ServiceNow para gerar automaticamente novas solicitações de infraestrutura.

## Conformidade e gerenciamento de políticas

O OpenTofu pode ajudar você a aplicar políticas sobre os tipos de recursos que
os times podem provisionar e usar.
Os processos de revisão baseados em tickets são um gargalo que pode atrasar o
desenvolvimento.
Em vez disso, você pode usar o Sentinel, uma estrutura de política como código,
para aplicar automaticamente políticas de conformidade e governança antes que o
OpenTofu faça alterações na infraestrutura.
As políticas do Sentinel estão disponíveis em backends na nuvem.

## Configuração de aplicações PaaS

Plataformas como Serviço (PaaS), como o Heroku, permitem criar aplicações web e
adicionar complementos, como bancos de dados ou provedores de e-mail.
O Heroku pode escalar elasticamente o número de dynos ou workers, mas a maioria
das aplicações mais complexas exige muitos complementos e serviços externos.
Você pode usar o OpenTofu para codificar a configuração necessária para uma
aplicação Heroku, configurar um DNSimple para definir um CNAME e configurar o
Cloudflare como uma Rede de Distribuição de Conteúdo (CDN) para a aplicação.
O OpenTofu pode fazer tudo isso de forma rápida e consistente, sem a necessidade
de uma interface web.

## Redes definidas por software

O OpenTofu pode interagir com Redes Definidas por Software (SDNs) para
configurar automaticamente a rede de acordo com as necessidades das aplicações
em execução.
Isso permite migrar de um fluxo de trabalho baseado em tickets para um
automatizado, reduzindo o tempo de implantação.

## Kubernetes

O Kubernetes é um agendador de cargas de trabalho de código aberto para
aplicações conteinerizadas.
O OpenTofu permite implantar um cluster Kubernetes e gerenciar seus recursos
(por exemplo, pods, deployments, serviços etc.).

## Ambientes paralelos

Você pode ter ambientes de staging ou de QA que usa para testar novas aplicações
antes de lançá-las em produção.
À medida que o ambiente de produção cresce e se torna mais complexo, pode ser
cada vez mais difícil manter um ambiente atualizado para cada etapa do processo
de desenvolvimento.
O OpenTofu permite criar e desativar rapidamente infraestrutura para
desenvolvimento, teste, QA e produção.
Usar o OpenTofu para criar ambientes descartáveis conforme a necessidade é mais
econômico do que manter cada um indefinidamente.

## Demonstrações de software

Você pode usar o OpenTofu para criar, provisionar e inicializar uma demonstração
em vários provedores de nuvem.
Isso permite que as pessoas usuárias finais experimentem facilmente o software
em sua própria infraestrutura e até mesmo ajustem parâmetros como o tamanho do
cluster para testar as ferramentas de forma mais rigorosa em qualquer escala.
