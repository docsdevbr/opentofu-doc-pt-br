# O que há de novo no OpenTofu 1.10?

O OpenTofu 1.10 traz melhorias significativas na forma como você distribui e
gerencia seu código de infraestrutura, com suporte ao registro OCI, bloqueio de
estado S3 nativo e observabilidade aprimorada por meio do rastreamento do
OpenTelemetry.

## Suporte a registros OCI

O OpenTofu agora pode usar registros OCI (Open Container Initiative) para
distribuir provedores e módulos, permitindo que você utilize sua infraestrutura
de registro de contêineres existente para componentes de infraestrutura como
código.

Configure os espelhos do provedor de registro OCI em sua
[configuração da CLI](/docs/cli/config/config-file):

```hcl
provider_installation {
  oci_mirror {
    repository_template = "example.com/opentofu-providers/${namespace}/${type}"
    include             = ["registry.opentofu.org/*/*"]
  }
}
```

Use pacotes de módulos de registros OCI diretamente como um novo
[tipo de origem de módulo](/docs/language/modules/sources/):

```hcl
module "vpc" {
  source  = "oci://example.com/terraform-modules/vpc/aws"
}
```

Este recurso é particularmente valioso para ambientes isolados da internet e
organizações que desejam usar sua infraestrutura de registro de contêineres
existente.

Você pode encontrar mais informações sobre os formatos de artefatos OCI do
OpenTofu e instruções para criar seus próprios artefatos em
[Integrações de registros OCI](/docs/main/cli/oci_registries/).

## Bloqueio de estado S3 nativo

O backend S3 agora oferece suporte ao bloqueio de estado nativo sem a
necessidade do DynamoDB, simplificando sua infraestrutura e reduzindo custos.

```hcl
terraform {
  backend "s3" {
    bucket       = "meu-estado-opentofu"
    key          = "prod/opentofu.tfstate"
    region       = "us-east-1"
    use_lockfile = true  # Ativar bloqueio nativo do S3
  }
}
```

Este recurso aproveita as gravações condicionais do S3 para fornecer bloqueio de
estado confiável usando apenas o seu bucket S3.
A migração do bloqueio baseado em DynamoDB é simples, com suporte para bloqueio
duplo durante o período de transição.
Consulte a
[documentação do backend S3](../language/settings/backends/s3.mdx#s3-state-locking)
para obter detalhes.

## Rastreamento OpenTelemetry (experimental)

Depure e otimize suas operações do OpenTofu com o suporte integrado ao
OpenTelemetry.
O rastreamento está desativado por padrão para garantir a privacidade.

Habilite o rastreamento definindo as variáveis de ambiente:

```bash
export OTEL_TRACES_EXPORTER=otlp
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
export OTEL_EXPORTER_OTLP_INSECURE=true
```

O OpenTofu enviará rastros para o seu coletor configurado (como Jaeger ou
Grafana Tempo), ajudando você a identificar gargalos de desempenho e depurar
operações complexas.
Saiba mais na [documentação de rastreamento](../internals/tracing.mdx).

Observe que nenhum dado de telemetria é enviado para o OpenTofu ou qualquer
serviço externo, a menos que você o configure explicitamente.

## Arquivos de destino e exclusão

As novas opções `-target-file` e `-exclude-file` permitem gerenciar o
direcionamento de recursos por meio de arquivos versionados:

```bash
tofu plan -target-file=targets/production.txt
tofu apply -exclude-file=excludes/experimental.txt
```

O formato do arquivo é simples: um endereço de recurso por linha, com suporte
para comentários.

```
# Componentes de infraestrutura crítica
module.networking.aws_vpc.main
module.networking.aws_subnet.public[*]

# Infraestrutura de banco de dados
module.database.aws_db_instance.primary
```

Este recurso é perfeito para pipelines de CI/CD, implantações em fases e
colaboração de times.

## Bloqueio do cache global do provedores

Operações simultâneas do OpenTofu agora podem compartilhar o cache do provedor
com segurança, evitando corrupção e conflitos em ambientes de CI/CD e ao usar
ferramentas como o Terragrunt.

Habilite o cache global com:

```bash
export TF_PLUGIN_CACHE_DIR=/caminho/para/o/cache/compartilhado
```

O bloqueio em nível de sistema de arquivos garante que apenas um processo possa
modificar um provedor por vez, enquanto os outros aguardam normalmente.
Isso torna o cache de provedores adequado para operações paralelas em larga
escala.

Você pode encontrar mais informações sobre como usar o cache global de
provedores na
[documentação do cache de provedores](../cli/config/config-file.mdx).

## Suporte a descontinuação (experimental)

As pessoas autoras de módulos agora podem marcar variáveis e saídas como
obsoletas, ajudando as pessoas usuárias a migrar para APIs mais recentes de
forma mais eficiente:

```hcl
variable "instance_type" {
  type        = string
  deprecated  = "Use var.compute_type em vez disso."
}

output "instance_ip" {
  value       = aws_instance.main.public_ip
  deprecated  = "Use output.instance_details para obter mais informações."
}
```

As pessoas usuárias verão avisos claros ao usar recursos obsoletos, tornando a
evolução do módulo mais gerenciável.

## Blocos `moved` e `removed` aprimorados

O bloco `moved` agora suporta a migração de recursos entre diferentes tipos,
incluindo suporte integrado para migração de `null_resource` para
`terraform_data`:

```hcl
moved {
  from = null_resource.exemplo
  to   = terraform_data.exemplo
}
```

O bloco `removed` agora suporta regras de ciclo de vida e provisionadores:

```hcl
removed {
  from = aws_instance.legada

  lifecycle {
    destroy = false
  }
}
```

Essas melhorias tornam a refatoração de infraestrutura mais poderosa e flexível.
Consulte a
[documentação de refatoração](../language/modules/develop/refactoring.mdx)
para obter mais detalhes.

## Provedores de chaves externos

A criptografia de estado agora oferece suporte completo a provedores de chaves
externos, permitindo a integração com suas ferramentas de gerenciamento de
segredos preferidas:

```hcl
terraform {
  encryption {
    key_provider "external" "password_manager" {
      command = ["op", "read", "op://opentofu/stateencryption"]
    }

    method "aes_gcm" "state" {
      keys = key_provider.external.password_manager
    }

    state {
      method = method.aes_gcm.state
    }
  }
}
```

Você também pode encadear provedores de chaves para maior segurança.
Saiba mais na
[documentação de encriptação de estado](../language/state/encryption.mdx#key-providers).

## Alterações significativas

### Requisitos de plataforma

- **Linux**: agora requer o kernel 3.2 ou posterior;
- **macOS**: agora requer o macOS 11 (Big Sur) ou posterior;
- **Windows**: tratamento de links simbólicos mais conservador.

### Imagem Docker

A imagem `ghcr.io/opentofu/opentofu` não é mais suportada como imagem base.
Consulte
[criando sua própria imagem](../intro/install/docker.mdx#building-your-own-image)
para alternativas.

### Backend PostgreSQL

O mecanismo de bloqueio foi alterado.
Não utilize o OpenTofu 1.10 em paralelo com versões anteriores ao compartilhar o
mesmo banco de dados PostgreSQL, pois a implementação de bloqueio foi alterada.
A mistura de versões pode levar a gravações conflitantes e causar perda de
dados.

## Melhorias menores

- A função `element` agora suporta índices negativos: `element(list, -1)`
  retorna o último elemento;
- Novo sinalizador `-concise` para uma saída de automação mais limpa;
- O backend PostgreSQL suporta nomes de tabela personalizados para configurações
  com múltiplos projetos;
- O backend HTTP agora suporta desbloqueio forçado;
- Melhorias no desempenho da instalação dos provedores;
- Mensagens de erro aprimoradas para falhas de conversão de tipo;
- Novas funções integradas do provedor:
  - `provider::terraform::decode_tfvars` - decodifica o conteúdo de um arquivo
    TFVars em um objeto;
  - `provider::terraform::encode_tfvars` - codifica um objeto em uma string com
    o formato TFVars;
  - `provider::terraform::encode_expr` - codifica uma expressão em uma sintaxe
    válida do OpenTofu.
- O OpenTofu agora recomenda `-exclude` em vez de `-target` em mensagens de erro
  sobre valores desconhecidos em `count` e `for_each`.

## Correções de falhas

- Corrigido o erro de validação do nome do provedor no bloco `provider_meta`;
- O backend PostgreSQL não falha mais na criação do espaço de trabalho para
  retornos paralelos;
- Corrigido o tratamento de valores nulos nas funções `element`, `slice` e
  `values`;
- Resolvidos os problemas de encriptação de estado com interações com o backend;
- Corrigidas as melhorias na geração do bloco de importação;
- Melhor tratamento de erros de instalação dos provedores;
- Corrigidos os problemas no grafo de dependências com blocos de importação.

Para obter uma lista completa de alterações, consulte o
[changelog completo](https://github.com/opentofu/opentofu/blob/v1.10/CHANGELOG.md).
